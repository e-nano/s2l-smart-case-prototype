# S2L Smart Case stakeholder prototype

Open `index.html` in a modern browser. No installation, build step, package manager or internet connection is required.

## Suggested stakeholder route

1. Start in **Capture** and demonstrate local sample identity plus immutable sampling-trigger events.
2. Use **Complete to 25** to show the representative composite-sample target.
3. Open **Tray**, explain the ten temporary storage states, then place the filled pod on **Position 11**.
4. Show automatic RFID, QR and stable-weight commissioning, followed by returning the filled pod to any free tray position.
5. Toggle **Offline**, capture more evidence, and show queued records remaining valid locally.
6. Open **Map**, simulate an ambiguous GNSS boundary and confirm the audited manual-context path.
7. Reconnect and open **Records** to show synchronisation and server-side work reconciliation.
8. Open **Case** to review power, GNSS, connectivity, readers, weighing, storage and display health.

## Deliberate product boundary

The Smart Case is not job/order-aware. It stores operational geography and capture configuration locally, creates globally unique sample records offline, and synchronises them later. Any job, order or invoice linkage is performed by the server after synchronisation.

The current prototype also reflects the 8 September requirements review: a 5 m automatic-GNSS threshold, Area/geometry revision evidence on captured records, RUT241-class industrial 4G/Wi-Fi connectivity, and an approximately 10-inch sunlight-readable outdoor display using resistive touch unless testing proves an equal or better glove/wet-use alternative.

All information is fictional and held only in browser memory for the current page session.
